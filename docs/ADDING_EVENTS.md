# Как добавить или обновить мероприятие

В обычной работе используются админка и автоматический сборщик. ИИ-помощник ищет по опубликованному каталогу и не может сам публиковать события.

## Автоматический сбор

`config/sources.json` задаёт официальные сайты, страницы афиш и сведения о площадках. Процесс `sources` обращается к сайтам, соблюдает ограничения загрузки и `robots.txt`, разбирает страницы и сохраняет их снимки. Обновление запускается вместе с приложением, затем каждые шесть часов.

Порядок обработки:

```text
Страница учреждения → исходная запись → проверка полей и площадки
                                             ↓
                           новый сеанс / обновление / возможный дубль
                                             ↓
                           публикация проверенного / модерация спора
```

У каждой карточки есть ссылка на первоисточник. Неизвестные цена, возраст или окончание не заполняются догадками. Исчезновение записи с одной страницы само по себе не считается доказанной отменой мероприятия.

Начальная загрузка при запуске отличается от сетевого сбора: она берёт сохранённые реальные данные из `data/open/`, если база пустая. Дата снимка сохранена в `manifest.json`; такая загрузка не ставит текущую дату как дату новой проверки сайта. Затем сборщик получает свежую афишу.

Принудительно выполнить сбор:

```bash
docker compose exec sources uv run --no-sync python -m app.cli.collect_sources --publish-verified
```

Результаты видны в админке в разделе «Сборы», спорные записи — в «Модерации». Чтобы добавить новый сайт, настройте источник; если разметка отличается, потребуется поддержка его формата в парсере.

## Ручное добавление

1. Открыть http://localhost:8081/admin и войти значением `ADMIN_API_TOKEN` из своего `.env`.
2. В разделе «Карточки» нажать «Создать карточку».
3. Заполнить сведения и сохранить. Запись появится как черновик.
4. Проверить дату, адрес, цену, возраст и первоисточник.
5. Выбрать действие «Опубликовать», написать причину и нажать «Применить».

До публикации черновик не виден пользователям. Для отмены выбрать «Отменить» с причиной. История хранится в «Аудите». Если карточка была изменена другим администратором, приложение попросит обновить её вместо перезаписи чужого изменения.

## Импорт файла

В разделе «Импорты» укажите название источника, выберите CSV/JSON и нажмите «Импортировать». Название источника используйте одинаковое при повторной загрузке той же афиши.

Обязательные поля одной записи:

| Поле | Что указать |
|---|---|
| `external_id` | Постоянный идентификатор сеанса у источника |
| `title` | Название мероприятия |
| `category` | `concert`, `theatre`, `exhibition`, `festival`, `cinema`, `excursion` или `other` |
| `date_start` | Начало с часовым поясом, например `2026-11-15T18:00:00+05:00` |
| `city` | Город |
| `venue` | Название площадки |
| `address` | Адрес |
| `description` | Описание |
| `source_url` | Ссылка на источник сведений |

Дополнительные поля: `date_end` или `duration_min`, `price_min`, `price_max`, `is_free`, `age_limit`, `language`, `org_link`, `tags`. В JSON даты — строки, цены — рубли, `is_free` — `true`/`false`; в CSV для неизвестных значений оставляйте пустую ячейку. Допустимые возрастные ограничения: 0, 6, 12, 16, 18. В CSV теги разделяются точкой с запятой. Неизвестный возраст не означает 0+.

Если цена указана как «от 400 ₽», передайте только `price_min=400`. Такая запись не подтверждает, что билет укладывается в бюджет до 700 ₽. `is_free=true` ставится только при подтверждённом бесплатном входе.

CSV-шаблон: [import-template.csv](../data/import-template.csv). Реальный пример JSON: [sgtko.json](../data/open/sgtko.json). Полная схема: [event.schema.json](../data/event.schema.json). По умолчанию файл ограничен 2 МБ и 2000 строками.

Отчёт показывает результат каждой строки: добавлена, изменена, не изменилась, отклонена или отправлена на модерацию. Валидные строки могут быть загружены, даже если другие строки содержат ошибки. Загруженные черновики нужно проверить и опубликовать отдельно.

Один и тот же `external_id` с тем же источником используется для обновления существующего сеанса. Другая дата показа — другой сеанс и другой ID. Совпадение разных источников проверяется по сведениям о событии; противоречия требуют решения модератора. Повторный импорт не должен оживлять отменённое событие.

Для разработчика предусмотрены те же операции в http://localhost:8000/docs: импорт, создание, редактирование, публикация, отмена и модерация. Для авторизации нажмите «Authorize» и укажите свой ключ администратора.
