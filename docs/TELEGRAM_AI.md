# ИИ в Telegram

Бот: https://t.me/Afisha_bashkirii_bot. После обновления можно писать обычным сообщением: «Уфа», «давай что-нибудь на вечер», «дешевле», «ещё». `/chat` начинает новый диалог, `/search` открывает поиск по кнопкам, `/cancel` сбрасывает условия. Если бот ожидает цену, дату или название после команды, сначала завершите ввод либо используйте `/chat`.

Используется общий агент сайта: проверка условий, инструменты каталога, история, учёт токенов, лимиты расходов и резервный поиск. Диалог помечается каналом `telegram`; подписка по просьбе в этом канале создаётся для Telegram после отдельного подтверждения кнопкой. Предложения проверяют владельца, срок действия и неизменность содержимого. Запросить подписку и подтвердить её — разные действия.

Поиск возвращает до трёх событий одним сообщением со ссылками на источники. Следующая подборка удаляет предыдущее сообщение с результатами, ID которого сохранён после отправки самим ботом. Сообщения пользователя и уведомления не удаляются. Удаление старого сообщения ограничено правилами Telegram; если сообщение уже удалено или слишком старое, бот отправляет новую подборку. Источник ограничений: [Telegram Bot API, deleteMessage](https://core.telegram.org/bots/api#deletemessage).

Обновление Telegram сначала сохраняется в PostgreSQL вместе с заданием агента и смещением polling. Сетевой вызов модели выполняется после завершения транзакции. Ключ запроса — `telegram:<update_id>`: повтор использует сохранённый ответ. Незавершённое платное обращение после сбоя не запускается повторно автоматически. Готовые ответы отправляются через сохраняемую очередь; при сетевом сбое отправки невозможно обещать абсолютное отсутствие дублей.

Настройки `LLM_*` передаются контейнеру `bot` из `.env`, как и API. После изменения настроек или кода:

```powershell
docker compose build bot
docker compose up -d --no-deps bot
```

Проверки: тесты памяти и подтверждений, запрета чужого подтверждения, повторного `update_id`, восстановления готового ответа без повторного вызова модели, удаления только предыдущей подборки, сохранения ID сообщения после перезапуска, Telegram 400/429 и корректной страницы «ещё». Набор: `tests/test_bot_agent.py`, `tests/test_bot_compact.py`, `tests/test_bot_delivery.py` — 12 тестов прошли.

Обработчик Telegram отдельно вызван с настоящим Cloud.ru для «Уфа → давай что-нибудь на вечер»: оба запроса выполнили `search_events` в режиме `agent`, период и город сохранены, ответ сформирован одним сообщением. Проверка не отправляла сообщения Telegram и не меняла polling offset. Локальный отчёт не включён в репозиторий. Получение ответа в реальном чате следует проверить, отправив боту свой запрос.
